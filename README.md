# poler-mesh

**Единый MCP-диспетчер POLER-сети: один токен агента → вся экосистема.**

poler-mesh поднимает узлы сети (poler-git, poler-engine, будущие почта/диск)
как дочерние процессы, объединяет их MCP-инструменты в один `tools/list`
и маршрутизует `tools/call` нужному узлу. Агент видит ОДИН сервер с ОДНИМ
токеном — и получает гит, блокноты, поиск и всё, что подключат дальше.

**v0.2.0 — poler-wire: туннели больше не нужны.** Машина владельца сама
подключается исходящим каналом к своему `poler-relay` (ваш VPS), а агент
стучит в релей обычным HTTP. Ноль входящих портов, ноль сторонних сервисов,
End-to-End шифрование (Ed25519 + X25519 + ChaCha20-Poly1305) — релей видит
только размер и время. Спецификация — `docs/wire.md`.

```
[агент: GLM/Gemini/curl]      [ваш VPS]                 [ваш ПК]
  HTTP POST /mcp*  ───▶  poler-relay  ◀─── исходящий TCP (poler-wire v1) ───  poler-mesh --mcp-link
  (Bearer или sealed)    (слепой хаб)                                        (Hub: git+engine+…)
```

```
                    ┌─────────────────────────────────────┐
  агент ──token──▶  │  poler-mesh                         │
  (CLI/HTTP)        │  tools/list = union всех узлов      │
                    │  tools/call → маршрут к узлу        │
                    └───────┬──────────┬──────────┬───────┘
                       stdio│      stdio│      stdio│
                    ┌───────▼──┐ ┌─────▼────┐ ┌───▼──────┐
                    │poler-git │ │poler-    │ │ почта/   │
                    │(весь гит)│ │engine    │ │ диск ... │
                    └──────────┘ │(NLM,web) │ └──────────┘
                                 └──────────┘
```

Почему так (уроки p3-agent-cell): между хабом и узлами — пайпы ОС,
ноль открытых портов, ноль git-коммитов как транспорта, ноль общих
симметричных секретов. PAT провайдеров остаются внутри своих узлов.
Наружу — один `POLER_MESH_TOKEN`.

## Быстрый старт

```bash
poler-mesh init              # создать ~/.config/poler-mesh/mesh.toml
poler-mesh --nodes           # диагностика: поднять узлы, показать инструменты

# хаб как stdio-узел (для вызова из другого CLI):
poler-mesh --mcp-stdio

# хаб как HTTP-сервер в ЛОКАЛЬНОЙ сети (или пока через туннель):
poler-mesh --mcp-http 127.0.0.1:8770 --mcp-token <секрет>

# v0.2.0: удалённый доступ БЕЗ туннелей — см. раздел «poler-wire» ниже
```

Без `--config` хаб ищет `~/.config/poler-mesh/mesh.toml`; если файла нет —
честный автопоиск `poler-git`/`poler-engine` в PATH (в диагнозе видно,
что реально найдено).

## mesh.toml

```toml
[[node]]
id = "git"
cmd = "poler-git"
args = ["--mcp-stdio"]

[[node]]
id = "engine"
cmd = "poler-engine"
args = ["--mcp"]

# Новый узел — тем же паттерном (любой язык, ~100 строк):
# [[node]]
# id = "mail"
# cmd = "poler-mail"
# args = ["--mcp-stdio"]
```

## Как это работает

1. **Спавн**: каждый узел запускается как процесс с piped stdin/stdout
   (stderr наследуется — логи узлов видны в консоли хаба).
2. **Рукопожатие**: `initialize` + `notifications/initialized` (MCP,
   line-delimited JSON-RPC 2.0 — общий стандарт POLER).
3. **Реестр**: `tools/list` каждого узла → карта «имя → узел».
   Конфликт имён решает первый узел; конфликт репортится в stderr.
   Каждый инструмент помечается `_mesh_node` — видно происхождение.
4. **Маршрутизация**: `tools/call` уходит узлу-хозяину имени;
   ответ возвращается агенту как есть. Неизвестное имя — честный
   `isError` со списком доступных.
5. **Один токен**: HTTP-режим проверяет `Authorization: Bearer …`;
   токен — `--mcp-token` или env `POLER_MESH_TOKEN`, без него
   генерируется и печатается при старте.

## poler-wire v1: свой транспорт вместо туннелей (v0.2.0)

Проблема туннелей (localhost.run/cloudflared/Tailscale): чужой протокол,
владелец протокола видит граф, бесплатный шлюз падает по таймауту —
проверено на практике. Решение — собственный канал из трёх ролей:

| Роль | Кто | Запуск |
|---|---|---|
| релей | ваш VPS | `poler-relay --init` → `poler-relay` |
| link-клиент | ваш ПК | `poler-mesh --init-link` → `poler-mesh --mcp-link VPS:8771 --relay-key <b64> --agent glm=<b64>` |
| агент | GLM/Gemini/… | `scripts/poler_agent.py` (sealed) или `curl` (plain) |

Разворачивается один раз одной командой на каждой стороне. Дальше клиент
держит исходящее соединение (NAT неважен), переживает обрывы (бэкофф
1→2→4…60 с с джиттером) и пингует каждые 25 с.

**Криптография** (docs/wire.md): handshake — Ed25519-подписи с пиннингом
ключа релея; сессия — X25519 ECDH → HKDF-SHA256 → ChaCha20-Poly1305
(строго монотонный seq); агентские конверты — E2E: релей проверяет
подпись над ШИФРОТЕКСТОМ и маршрутизирует, расшифровать не может.
Идемпотентность — кэш `cmd_id` (TTL 300 с); анти-replay — nonce + окно
±300 с. Из зависимостей только чистые криптопримитивы RustCrypto,
ни tokio, ни WebSocket, ни TLS — свой кадр поверх голого TCP.

**Режимы агента**:
- `POST /mcp` + `Authorization: Bearer <token>` — plain: релей видит тело
  (только для доверенных сетей/тестов, curl-совместимо);
- `POST /mcp-sealed` + конверт — sealed: сквозное шифрование, релей слеп
  (нужен `poler_agent.py` или своя реализация по docs/wire.md §4);
- `GET /health` — версия + кто онлайн (без авторизации).

## Как написать узел сетки

Любая программа, которая:
- читает line-delimited JSON-RPC 2.0 из stdin, пишет в stdout;
- отвечает на `initialize` (serverInfo), `tools/list`, `tools/call`;
- логирует в stderr (не stdout!).

Готовый шаблон на 100 строк: `poler-mesh --mock-node demo`
(исходник — `src/mock.rs`). Именно так тестируется сама сетка.

## HTTP API

- `GET /health` — статус без авторизации (проверка туннеля)
- `POST /` или `POST /mcp` — JSON-RPC 2.0 c `Authorization: Bearer <token>`
- лимиты: 16 соединений, тело ≤ 8 МБ, idle 65 с

## Тесты

```bash
cargo test                # 62 теста: 52 unit + 10 integration
```

Unit покрывают кадрирование, AEAD-сессии, replay/идемпотентность,
конверты (вскрытие/подмена/чужой получатель). Integration поднимают
ПОЛНЫЙ стек: poler-relay + poler-mesh --mcp-link + мок-узел — и гоняют
через HTTP оба режима (plain 401/502/504, sealed подмена/replay/идемпотентность,
реконнект после смерти клиента). Живой тест реальной сетки —
`scripts/mesh_live_test.py`; живой тест transport-уровня —
`scripts/poler_agent.py` против запущенного релея.

## Известные ограничения v0.2

- один JSON-RPC вызов на HTTP-запрос (batch — в v0.3)
- ресурсы/prompts MCP не пробрасываются (только tools)
- plain-режим не идемпотентен (релей генерирует cmd_id на каждый POST);
  полный контракт ретраев — только в sealed-режиме
- forward secrecy на client-leg нет (Double Ratchet — будущая версия)
- `notifications/tools/list_changed` от узлов пока игнорируются
